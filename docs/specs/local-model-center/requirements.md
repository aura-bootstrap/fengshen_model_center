# Requirements Document

## Introduction

在项目独立目录 `src/model_center` 中建设本地模型管理中心，集中展示峰神切片生成器使用的本地模型、调用语言、用途、组成依赖、文件位置和磁盘体积。中心面向本机模型资产盘点与路径登记，不把“发现文件”等同于“模型可信或推理可用”，也不把权重大小等同于运行内存或显存需求。

首期范围包括模型目录、受限本地扫描、外置路径登记、容量统计、重复文件线索、按需 SHA-256 计算和中文管理界面；新增准入约束：纳入中心交付组件管理的非 Go 模型执行代码必须先形成可独立交付的二进制组件，不以源码加宿主机开发环境作为最终交付。已有四个 Go 初稿文件仅作为后续设计输入，不代表本功能已经实现或通过验证；本规格不预先批准其接口和实现细节。

本轮增量增加：当前版本隐藏自定义 URL 模型功能及其 UI，提供模型管理中心本身的启动与运行试用入口，并将中心和模型组件纳入既有依赖检查。中心仍可独立运行；客户端集成只涉及上述入口、功能可见性和只读依赖状态，不自动写回模型路径、不迁移已保存配置、不改授权流程或模型文件。运行中心不等于执行模型推理，也不授权中心启停推理服务。

Requirement 1–14 与增量设计已纳入用户“执行所有任务”的批量实施授权。按同步后的任务依赖执行编码与自动化验收；未通过的构建、平台测试和真实界面验收保持未完成，不提交、推送、发布或修改生产环境。

## Requirements

### Requirement 1: 独立模块与本机使用边界

**User Story:** As a 项目维护者, I want 在独立目录维护本地模型中心, so that 能够集中盘点模型而不改变既有三端运行行为。

#### Acceptance Criteria

1. THE SYSTEM SHALL 将模型中心的实现、界面资源和自动化测试放在 `src/model_center` 独立目录中，不要求启动现有三端客户端、Billing 服务或 Generation 服务才能查看模型资产。
2. THE SYSTEM SHALL 支持显式指定项目根目录和登记数据目录；WHEN 未指定项目根目录 THEN THE SYSTEM SHALL 仅通过可验证的项目目录特征定位根目录，定位失败时给出中文错误，不得把任意当前目录当成有效项目。
3. THE SYSTEM SHALL 将路径登记数据存放在独立的本机数据目录中，不写入现有三端配置、模型缓存配置或服务器配置。
4. WHILE 使用模型中心 THEN THE SYSTEM SHALL 保持现有授权、普通切片、音色处理、视频生成及已有高光任务快照的执行语义不变；当前版本新增配置入口的隐藏与依赖检查集成 SHALL 按 Requirement 12–14 执行，不将其解释为自动替换现有推理链。
5. THE SYSTEM SHALL 在界面明确说明路径登记仅用于管理中心盘点，不会自动使用户版、开发版或其他模型消费者采用该路径。

### Requirement 2: 模型目录、用途与调用语言

**User Story:** As a 使用者, I want 看到项目实际使用的模型及其用途和调用方式, so that 能区分必要组成、可选能力和不同推理环境。

#### Acceptance Criteria

1. THE SYSTEM SHALL 提供高光 Whisper 转写、可选 Whisper VAD、本地文本模型、可选本地视觉模型、Demucs htdemucs、Demucs htdemucs_ft、Seed-VC 主模型、Seed-VC Whisper Small、CAMPPlus、BigVGAN、正脸 Haar 和侧脸 Haar 共十二个本地模型目录项。
2. THE SYSTEM SHALL 为每个目录项展示名称、模型家族、功能类别、用途、调用语言或进程链、推理运行环境、可选性，以及已知的组成依赖。
3. THE SYSTEM SHALL 区分“Go → whisper.cpp 原生推理”“Go → 本地 HTTP 模型服务”“Go → Python/PyTorch”和“Go 直接读取 Haar 模型”四类调用方式，不得把所有模型标为 Python 推理。
4. THE SYSTEM SHALL 区分高光转写 Whisper 与 Seed-VC 使用的 Whisper Small，并展示 Seed-VC 对 Whisper Small、CAMPPlus、BigVGAN 的依赖关系，以及 htdemucs_ft 的四份子模型组成。
5. IF 实际型号由现有消费者配置决定且管理中心未取得可靠证据 THEN THE SYSTEM SHALL 显示“型号未确认”或等义状态，不得根据测试示例、文件扩展名或模型家族猜测具体型号、量化档或参数规模。
6. THE SYSTEM SHALL 将纯算法能量 VAD、参考声音文件、Python 运行环境及第三方仓库中未接入产品的模型与本地模型权重区分；云端模型如被展示 SHALL 单独标为远程服务引用，不计入本地权重目录和本地权重总量。

### Requirement 3: 受限扫描与可靠识别

**User Story:** As a 使用者, I want 扫描项目已知模型目录和我登记的位置, so that 无需遍历整台电脑也能找到模型并复核识别依据。

#### Acceptance Criteria

1. THE SYSTEM SHALL 默认仅扫描项目内已知模型目录、Seed-VC 检查点目录、用户 Torch 检查点目录，以及两份项目 Haar 模型的明确位置，并展示实际扫描范围；不存在的默认缓存目录 SHALL 作为未发现位置处理而不是整体失败。
2. WHEN 用户显式登记外置文件或目录 THEN THE SYSTEM SHALL 仅将该位置加入对应模型的扫描范围，不扫描所在盘符、父目录或相邻目录。
3. THE SYSTEM SHALL 使用明确文件名、组成清单或可复核的缓存仓库身份识别已知模型；仅扩展名相符或位于登记目录内的文件 SHALL 不被直接认定为已确认型号。
4. THE SYSTEM SHALL 对无法自动确认身份的外置权重显示“已登记、身份未确认”及其文件证据，不得因用户登记就声称文件与目录模型匹配。
5. THE SYSTEM SHALL 在扫描中跳过版本控制目录和缓存锁目录，不递归跟随目录链接；对文件链接 SHALL 解析目标并验证其位于已允许的扫描范围，否则仅报告未计入的链接。
6. THE SYSTEM SHALL 对扫描文件数量和执行时间设置明确上限，并支持取消；IF 达到上限、权限不足、文件消失或单个根目录不可访问 THEN THE SYSTEM SHALL 保留其他已取得结果，将受影响范围标为未完成并展示诊断。
7. WHILE 执行普通扫描 THEN THE SYSTEM SHALL 仅读取识别和统计所需的文件系统元数据，不加载权重、不反序列化模型、不执行脚本，也不为判重读取所有权重正文。

### Requirement 4: 路径登记与持久化

**User Story:** As a 使用者, I want 登记存放在其他目录的模型, so that 重启管理中心后仍能找到自己的模型资产。

#### Acceptance Criteria

1. WHEN 登记模型路径 THEN THE SYSTEM SHALL 校验模型目录项、绝对路径、目标可访问性及普通文件或目录类型；无效输入 SHALL 返回明确中文错误，且不覆盖原有登记。
2. WHEN 登记单个文件 THEN THE SYSTEM SHALL 校验该目录项允许的文件类型；WHEN 登记目录 THEN THE SYSTEM SHALL 按对应模型的识别规则展示匹配文件和身份未确认文件，不将目录内所有权重都算作该模型的必需组成。
3. WHEN 保存或取消登记 THEN THE SYSTEM SHALL 仅更新独立登记数据，不移动、复制、重命名、删除或修改原始模型文件。
4. THE SYSTEM SHALL 以避免半写入文件的方式保存登记数据，并保证并发更新不会丢失已成功保存的其他登记；IF 持久化失败 THEN THE SYSTEM SHALL 保留此前有效登记并向界面报告失败。
5. WHEN 登记数据损坏或已登记路径随后失效 THEN THE SYSTEM SHALL 明确显示对应错误，不静默丢弃登记、不覆盖损坏数据，也不回落到可能属于其他型号的文件。
6. WHEN 重启管理中心 THEN THE SYSTEM SHALL 恢复已成功保存的登记，并允许用户明确取消登记以重新使用默认发现规则。

### Requirement 5: 容量统计与重复文件证据

**User Story:** As a 使用者, I want 看到真实文件大小和缓存重复线索, so that 能区分模型本体、缓存副本与推理运行环境的空间成本。

#### Acceptance Criteria

1. THE SYSTEM SHALL 为已发现文件保留精确字节数，并以明确标注的 MiB 或 GiB 展示人类可读容量；换算 SHALL 使用 1024 进制，不混用 MB、GB 标记。
2. THE SYSTEM SHALL 分开展示每个模型的已识别权重逻辑大小、扫描范围内全部文件的逻辑大小，以及可确认的运行环境目录逻辑大小；目录不存在或未扫描时 SHALL 显示未知或未发现，不伪报为已测量的零。
3. THE SYSTEM SHALL 明确统计范围和包含关系，不将权重、缓存总量与包含该缓存的父目录总量重复相加，也不将逻辑文件大小总和标为物理磁盘分配大小。
4. THE SYSTEM SHALL 区分同一路径、可识别的硬链接、文件链接及不同路径的普通文件副本；IF 文件身份不能可靠确认 THEN THE SYSTEM SHALL 披露统计局限，不宣称已经得到物理去重后的唯一占用。
5. THE SYSTEM SHALL 将仅同名或同大小的文件标为重复候选，不据此合并不同修订或不同内容的权重；只有取得相同内容摘要等明确证据后 SHALL 标为内容相同，且不得仅凭摘要推断全部副本均可安全删除。
6. THE SYSTEM SHALL 允许查看组成文件和路径以解释 Seed-VC 多模型合计、htdemucs_ft 四份子模型合计，以及 Hugging Face blobs/snapshots 的普通文件副本情况；多个目录项引用同一文件时 SHALL 说明共享关系，避免在全局文件总量重复计数。
7. THE SYSTEM SHALL 明确权重磁盘体积不代表运行 RAM、VRAM 或吞吐能力；未进行相应测量时 SHALL 不展示虚构的内存、显存需求和性能结论。

### Requirement 6: 文件状态与完整性校验

**User Story:** As a 使用者, I want 区分文件发现、组成齐全和校验结果, so that 不会把盘点结果误认为模型已经安全且可运行。

#### Acceptance Criteria

1. THE SYSTEM SHALL 分别表达未发现、已登记但身份未确认、已发现文件、组成不完整、不可访问、空文件、扫描未完成和正在校验等适用状态，并展示状态依据。
2. WHEN 检查 htdemucs_ft THEN THE SYSTEM SHALL 仅在四个预期子模型均存在且非空时标为组成齐全；WHEN 检查 Seed-VC THEN THE SYSTEM SHALL 分开展示主模型与三项配套依赖状态，不以主模型存在代替全部依赖齐全。
3. THE SYSTEM SHALL 将“文件已发现”“已知组成齐全”“已计算 SHA-256”“与预期摘要一致”和“已通过推理测试”视为不同证据，不在未执行相应检查时展示后者。
4. WHEN 用户显式请求 SHA-256 THEN THE SYSTEM SHALL 仅校验当前目录项允许访问的目标文件，采用有界缓冲读取并支持取消，不在每次刷新时自动对全部大文件计算摘要。
5. IF 校验期间文件大小、修改时间或可检测的文件身份发生变化，或读取失败 THEN THE SYSTEM SHALL 将此次校验标为失败或已失效，不返回有效校验结论。
6. IF 未提供可信的预期摘要 THEN THE SYSTEM SHALL 仅报告当前文件 SHA-256 指纹，并明确其不代表发行方认证、无恶意内容、格式正确或推理可用；本期 SHALL 不自动访问外网获取预期摘要。
7. WHEN 文件在后续扫描中发生变化 THEN THE SYSTEM SHALL 使此前校验结果失效或标为历史结果，并保留校验时间和对应文件身份，不将旧摘要当成当前状态。

### Requirement 7: 运行环境与消费者关系

**User Story:** As a 使用者, I want 知道每类模型由什么组件消费, so that 能判断文件缺失和运行环境缺失分别需要在哪里处理。

#### Acceptance Criteria

1. THE SYSTEM SHALL 展示 Whisper 所需的原生 CLI、Demucs 和 Seed-VC 所需的 Python/PyTorch 环境、本地文本和视觉模型所需的独立 HTTP 服务，以及 Haar 由 Go 读取的消费者关系。
2. THE SYSTEM SHALL 将可执行文件或运行环境目录的发现状态与模型权重发现状态分开；仅发现 Python、whisper.cpp 或模型文件 SHALL 不推断相应推理链可用。
3. THE SYSTEM SHALL 对本地 HTTP 模型显示其服务型接入属性；IF 权重由 Ollama 等外部服务管理且管理中心未登记可靠文件位置 THEN THE SYSTEM SHALL 将本地权重容量标为未知，不以服务模型名称猜测路径或体积。
4. THE SYSTEM SHALL 说明本期不检测模型推理服务存活、不启动模型推理、不验证 GPU/CUDA 兼容性，也不通过运行第三方脚本获取版本；模型管理中心自身的启动与健康确认 SHALL 按 Requirement 13–14 执行，不等同于检测模型服务。
5. THE SYSTEM SHALL 不读取现有消费者的 API Key、秘密修订、令牌或模型原始请求；不得以取得这些秘密作为盘点前提。

### Requirement 8: 中文管理界面与操作反馈

**User Story:** As a 使用者, I want 在清晰的中文界面完成盘点、定位和校验, so that 不依赖命令行也能理解本机模型状态。

#### Acceptance Criteria

1. THE SYSTEM SHALL 提供简体中文本机管理界面，包含统计概览、模型列表和模型详情，并使名称、用途、调用语言、状态和容量可以直接查阅。
2. THE SYSTEM SHALL 支持按模型名称、家族或用途搜索，并按功能类别、运行环境和文件状态筛选；WHEN 无匹配结果 THEN THE SYSTEM SHALL 提供明确空态及清除筛选入口。
3. THE SYSTEM SHALL 提供刷新扫描、登记或取消路径、查看组成文件和按需计算 SHA-256 的实际操作，不展示未接通接口的可用按钮。
4. WHILE 扫描或校验执行中 THEN THE SYSTEM SHALL 展示对应操作状态和取消入口，避免重复触发同一目标的相同操作；取消后 SHALL 明确区分未完成结果与成功结果。
5. THE SYSTEM SHALL 展示扫描范围、扫描时间和结果是否完整，并在操作失败时保留仍有效的列表与登记内容，不以空白页面掩盖错误。
6. THE SYSTEM SHALL 在窄窗口下保持核心操作可达，对长路径提供可读的展开或复制方式；状态 SHALL 同时使用文字表达，不仅依靠颜色。
7. THE SYSTEM SHALL 支持键盘访问核心控件、可见焦点和可访问名称；所有外部文件名、路径和错误内容 SHALL 作为文本呈现，不执行其中的 HTML 或脚本。

### Requirement 9: 本机网络与文件安全

**User Story:** As a 重视素材与设备隐私的使用者, I want 模型中心只服务本机且不泄露文件和秘密, so that 盘点操作不会扩大现有应用的网络和文件访问范围。

#### Acceptance Criteria

1. THE SYSTEM SHALL 仅监听回环 IP 地址，并拒绝非回环监听配置；本期 SHALL 不开放局域网、公网访问、远程账号或多用户服务。
2. THE SYSTEM SHALL 校验请求 Host、Origin 和适用的浏览器跨站请求信息，并对管理 API 使用每次启动重新生成的不可预测会话凭据，拒绝无效或缺失凭据的 API 请求。
3. THE SYSTEM SHALL 对 API 请求方法、请求体大小、未知字段和多余 JSON 内容进行校验；文件操作目标 SHALL 由有效模型目录项及受控登记解析，不接受任意路径的下载、读取、执行或校验接口。
4. THE SYSTEM SHALL 仅提供内置界面资源，不将项目根目录、登记目录或模型目录映射为可浏览的静态文件服务，也不返回模型二进制内容。
5. THE SYSTEM SHALL 在本机完成扫描、统计、登记与校验，不上传路径、文件名、摘要或模型文件，不引入外部 CDN、遥测、远程字体或在线页面资源。
6. THE SYSTEM SHALL 不在日志记录会话凭据、API Key、模型原始请求或响应；绝对路径 SHALL 仅在必要的本机界面、登记数据和诊断中使用，不发送到外部服务。
7. THE SYSTEM SHALL 使用禁止跨站嵌入、限制脚本与连接来源及禁止敏感结果缓存的浏览器安全策略；会话结束或服务停止后 SHALL 不继续接受管理 API 请求。

### Requirement 10: 自动化回归与验收证据

**User Story:** As a 维护者, I want 用不依赖真实大模型的测试验证管理中心, so that 后续扩展目录和文件操作不会破坏统计或安全边界。

#### Acceptance Criteria

1. THE SYSTEM SHALL 提供确定性临时目录测试，覆盖十二个目录项、已知文件识别、未知型号、空文件、缺失组成、失效登记、扫描上限、取消及局部失败隔离。
2. THE SYSTEM SHALL 提供容量测试，覆盖字节换算、父子目录重叠、同文件跨目录项引用、同名不同内容文件、普通文件副本，以及平台支持时的硬链接和文件链接；不支持的链接测试 SHALL 明确 SKIP。
3. THE SYSTEM SHALL 提供登记持久化测试，覆盖新增、替换、取消、重启恢复、损坏数据、写入失败及并发更新，证明原始模型文件与既有消费者配置未被修改。
4. THE SYSTEM SHALL 提供 SHA-256 测试，覆盖已知摘要、大文件流式读取、读取期间变更、失效结果、取消及未提供预期摘要时的措辞边界。
5. THE SYSTEM SHALL 提供 HTTP 安全测试，覆盖非回环监听拒绝、Host/Origin 校验、跨站访问、会话凭据、错误方法、超大或非法请求、路径越界、静态资源目录隔离及输出转义。
6. THE SYSTEM SHALL 提供界面回归测试，覆盖搜索筛选、路径登记与取消、扫描与校验取消、空态、失败反馈及长路径；实施验收时 SHALL 实际启动中心并在浏览器验证正常流程和至少一个错误流程，不以编译通过替代界面验收。
7. THE SYSTEM SHALL 使默认自动化测试无需外网、GPU、Python 环境或真实模型权重；未执行真实模型推理 SHALL 不报告为推理验证通过。
8. THE SYSTEM SHALL 通过限定改动范围及相关回归，证明除 Requirement 12–14 明确规定的功能隐藏、中心入口和依赖检查变化外，既有三端模型执行与授权合约未被改变；现有初稿在完成实现和上述验证前 SHALL 不被标记为交付完成。

### Requirement 11: 非 Go 模型执行代码的二进制组件准入（已确认增量）

**User Story:** As a 项目维护者, I want 非 Go 模型执行代码先形成可独立交付的二进制组件再纳入中心, so that 使用者无需准备源码和开发环境即可管理交付组件及其依赖。

#### Acceptance Criteria

1. THE SYSTEM SHALL 要求纳入中心交付组件管理的非 Go 模型执行代码具有对应的预编译可执行程序或可加载二进制库；仅有 `.cpp`、`.cu`、`.py` 源码或开发虚拟环境时 SHALL 标为未交付二进制组件，不显示组件已就绪。
2. WHEN 交付 C/C++ 模型执行组件 THEN THE SYSTEM SHALL 提供匹配目标操作系统和架构的预编译 EXE/DLL 或平台等价物，以及必需运行库，不要求使用者安装 CMake、C/C++ 编译器或 CUDA Toolkit 以完成首次启动编译；GPU 驱动要求 SHALL 独立声明。
3. WHEN 交付当前 Python 模型执行链 THEN THE SYSTEM SHALL 将项目执行入口编译或冻结打包为独立可执行组件，并随组件提供必要的解释器运行时、原生扩展和动态库，不要求使用者安装系统 Python、pip 或创建 venv；纯冻结打包 SHALL 明确标注为打包方式，不伪称已经移植为原生 Go/C++ 或彻底消除 Python 运行时。
4. THE SYSTEM SHALL 允许已经预编译的 PyTorch、CUDA 运行库及其他第三方二进制作为组件依赖，不要求重复编译其源码；交付物 SHALL 列明必需依赖，不承诺全部合并为单个 EXE，也不得假定 Go 能直接调用任意 PyTorch DLL。
5. THE SYSTEM SHALL 为每个交付组件记录组件 ID、版本、目标平台与架构、入口类型、构建或打包方式、文件相对路径、大小、SHA-256、必需运行库与模型权重引用；入口或必需文件缺失、摘要不符或平台不匹配时 SHALL 显示对应未就绪原因。
6. THE SYSTEM SHALL 将模型权重、Haar XML、配置及其他数据资源与可执行代码区分，不要求把权重编译成程序；管理中心的浏览器界面 HTML/CSS/JavaScript SHALL 继续作为内嵌资源，不将本条模型执行代码准入要求扩张为重写界面。
7. WHEN 盘点仅有源码的当前组件 THEN THE SYSTEM SHALL 保留其模型文件与容量信息，但将交付组件状态单独标为待构建；组件文件齐全与摘要匹配 SHALL 不提升为模型可推理或已通过真实推理验证。
8. WHEN 纳入 Whisper 流式执行组件 THEN THE SYSTEM SHALL 要求明确声明其支持中心所记录的流式协议和版本，并提供对应二进制文件；普通批处理 whisper-cli 或仅存在 Go 调用端 SHALL 不被标记为已具备流式组件，且未经执行验证的兼容声明 SHALL 仅作为声明展示。
9. THE SYSTEM SHALL 提供独立、显式运行的构建或打包流程和组件清单生成代码，使构建阶段可依赖编译器或打包工具，但中心正常运行与扫描 SHALL 不自动构建、安装依赖、执行组件、启动推理或写回既有三端。
10. THE SYSTEM SHALL 提供组件准入及打包产物测试，覆盖源码未构建、缺失文件、摘要不符、平台不匹配、受限相对路径和无宿主机 Python/编译器时的入口启动；构建产物未实际生成或启动测试未执行时 SHALL 明确标为未验证，不以清单存在代替可交付证据，启动测试 SHALL 不被报告为真实模型推理验证。

### Requirement 12: 当前版本隐藏自定义 URL 模型功能及 UI（已确认增量）

**User Story:** As a 使用者, I want 当前版本不再提供自定义 URL 模型接入功能和编辑界面, so that 可以先通过模型管理中心盘点本地模型，而不会误认为任意服务地址已经接通中心管理或推理。

#### Acceptance Criteria

1. THE SYSTEM SHALL 核对用户版、开发版和管理版中涉及自定义 URL 模型接入的配置入口、文本与操作，在当前版本隐藏相应功能及 UI，包括自定义本地文本服务和独立本地视觉服务的地址输入及其关联接入操作；不以仅隐藏 URL 输入框、仍保留可用接入按钮的方式满足本条。
2. WHILE 自定义 URL 模型功能被隐藏 THEN THE SYSTEM SHALL 不在当前配置与新建任务交互中提供新增、编辑、测试或启用该类接入的可操作入口；模型目录中对历史 HTTP 调用方式的只读说明 SHALL 不被当作可用接入入口。
3. THE SYSTEM SHALL 保留已有自定义 URL 配置、秘密引用及任务执行快照，不因隐藏 UI 而清空、覆盖或静默迁移这些数据；已有任务按其保存的快照执行，不自动切换到其他模型、云端或中心。
4. IF 新建任务仍依赖当前未提供的模型执行能力 THEN THE SYSTEM SHALL 明确提示能力尚未接通，不将“已打开中心”“已发现权重”或“组件文件齐全”当成可以启动新推理任务的依据，也不静默回退到其他执行路由。
5. THE SYSTEM SHALL 将自定义 URL 模型接入与既有受支持的云端 Provider 配置区分，不因本条隐藏所有云端模型管理、授权设置或与模型无关的服务地址；涉及的三端差异 SHALL 在设计中逐项列出。
6. THE SYSTEM SHALL 隐藏与被停用入口绑定的必填校验、保存提示和启用开关，避免用户被不可见字段阻断无关配置操作；无关字段保存 SHALL 保留被隐藏配置的原值。
7. THE SYSTEM SHALL 提供三端适用范围的界面及配置回归测试，覆盖入口不可达、关联操作不可用、已有配置及秘密引用保留、旧任务快照不变、无隐式路由切换和无关云端配置仍可使用。

### Requirement 13: 模型管理中心启动与本机运行试用（已确认增量）

**User Story:** As a 使用者, I want 从既有界面打开并试用本地模型管理中心, so that 可以先验证中心本身的盘点与管理流程，而不需要自行拼接命令或配置模型服务 URL。

#### Acceptance Criteria

1. THE SYSTEM SHALL 在适用客户端的既有模型配置或依赖管理区域提供“打开模型管理中心”的实际操作，不新增三端侧栏栏目；中心 SHALL 同时保留独立启动能力，不要求启动三端或远端服务。
2. WHEN 用户显式打开中心 THEN THE SYSTEM SHALL 检查可信本机中心实例，复用已确认的实例，或从受控交付位置启动中心二进制，并在确认中心身份与健康状态后打开其本机界面；不执行用户输入的任意程序、命令或 URL。
3. IF 中心二进制缺失、组件不匹配、启动失败、健康确认超时或监听地址被其他程序占用 THEN THE SYSTEM SHALL 显示明确中文诊断和可再次尝试的操作，不将请求已发送或浏览器已打开报告为中心已就绪，也不连接身份未确认的占用进程。
4. THE SYSTEM SHALL 区分中心进程状态、管理界面可访问状态、模型文件状态、执行组件状态与真实推理验证状态；运行试用在本期指中心自身的扫描、登记、容量和校验流程，不包括启动模型服务或执行模型推理。
5. THE SYSTEM SHALL 在设计中明确中心实例复用、并发打开、所属进程与退出策略；重复打开 SHALL 不重复创建冲突实例，客户端退出 SHALL 不终止由用户独立启动的中心或其他进程。
6. THE SYSTEM SHALL 对启动与健康确认沿用回环访问、安全凭据和来源校验边界；中心凭据 SHALL 不通过 URL 查询参数或日志暴露，面向依赖检查的状态 SHALL 不包含秘密或模型请求内容。
7. THE SYSTEM SHALL 提供启动与打开流程的自动化测试，覆盖首次启动、实例复用、并发打开、二进制缺失、端口冲突、错误身份、超时及独立运行；实施验收时 SHALL 真实启动中心并在浏览器验证正常流程和错误流程，未执行时明确标为未验证，不在规格编写阶段启动程序。

### Requirement 14: 既有依赖检查纳入模型中心与模型组件（已确认增量）

**User Story:** As a 使用者, I want 在既有依赖检查中看到模型中心和相关模型组件的状态, so that 可以区分管理工具缺失、权重缺失与执行组件未交付，而不把中心在线误认为模型能够推理。

#### Acceptance Criteria

1. THE SYSTEM SHALL 将模型中心纳入适用客户端与工作模式的既有依赖检查清单，并评估用户版、开发版和管理版的涉及面；设计 SHALL 明确各端各模式显示哪些项目及其实际状态来源，不增加没有后端结果来源的前端占位项。
2. THE SYSTEM SHALL 分开显示中心交付组件是否存在、中心是否正在运行或可访问，以及相关模型权重、必需组成和二进制执行组件的检查状态；仅存在源码、开发 venv 或权重文件 SHALL 不使执行组件检查通过。
3. WHEN 展示模型依赖 THEN THE SYSTEM SHALL 根据功能与模型关系说明 Whisper 原生组件及可选 VAD、Demucs 组成、Seed-VC 及其 Whisper Small/CAMPPlus/BigVGAN 配套依赖、Haar 数据和 Go 消费者的适用状态；不要求所有模式都安装全部可选模型。
4. THE SYSTEM SHALL 保持既有逐行明细、并发检查及逐项结果反馈机制，前端清单与后端检查 ID 和状态语义一致；模型中心项 SHALL 不破坏现有依赖项目和完成事件的处理。
5. IF 中心未安装、未运行、不可访问或相关可选模型组件缺失，且不影响当前模式必要能力 THEN THE SYSTEM SHALL 展示降级或未启用原因，不将其作为整个应用的致命失败；IF 当前操作确实依赖缺失组件 THEN THE SYSTEM SHALL 明确指出被阻断的具体能力。
6. WHILE 自动执行依赖检查 THEN THE SYSTEM SHALL 仅进行有界的组件元数据、已取得盘点结果或中心自身状态检查，不自动启动中心或模型推理、不下载或构建组件、不全量计算权重摘要，也不因中心不可用无限等待；未取得状态 SHALL 显示未知或未检查，不伪报通过。
7. THE SYSTEM SHALL 提供前后端清单一致性及状态映射测试，覆盖中心缺失、已安装但未运行、中心可访问、状态过期、组件待构建、权重不完整、可选项降级、必要能力阻断及检查取消；中心健康或组件完整 SHALL 不转换成“模型推理验证通过”。

## Out of Scope

- 中心运行时自动下载、安装、升级或卸载模型及 Python、PyTorch、Ollama、llama.cpp、whisper.cpp 等运行环境；显式开发构建阶段的二进制编译或打包按 Requirement 11 处理。
- 搬迁、删除、重命名模型，清理缓存，创建硬链接或以内容相同为由自动去重。
- 启停模型推理服务、执行模型脚本、自动推理冒烟、跑分或推断 RAM/VRAM 需求；中心自身的显式启动、打开与健康确认按 Requirement 13 处理。
- 取代现有用户版、开发版、管理版的整个模型配置工作区，向三端写回模型路径，或新增三端侧栏入口；现有区域内隐藏自定义 URL 模型功能、提供中心入口与依赖检查集成按 Requirement 12–14 处理。
- 读取、管理或同步云端与本地模型 API Key，修改现有秘密存储方式，或绕过设备及功能授权。
- 将 Python 音色处理链改写为 Go/C++/ONNX，或将第三方仓库的未使用分支接入产品。
- 全盘扫描、局域网或公网服务、远程模型文件管理、云端资产同步、遥测及后台自动联网。
- 本期生产部署、发布安装包、变更既有应用版本号，以及以文件盘点代替实际模型可用性验证。
